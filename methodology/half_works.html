§ 1.2

命令行安装

For the terminal native

三种平台我们都提供了包管理器源。Homebrew 仓库在国内有镜像，安装平均 8 秒搞定。如果你之前装过老版本，安装脚本会自动迁移配置和技能缓存。

需要 sudo 权限的只有 apt 路径。Homebrew 和 Winget 都不需要。

macOS · HomebrewSHELL
# 1. 添加仓库（首次需要）
brew tap workbuddy/tap

# 2. 安装 GUI 版
brew install --cask workbuddy

# 3. 或者只装 CLI
brew install workbuddy-cli
Windows · WingetPOWERSHELL
# Windows 10/11 默认带 winget
winget install WorkBuddy.WorkBuddy
winget install WorkBuddy.CLI      # 仅命令行版
Linux · aptBASH
# Ubuntu 22.04+ / Debian 12+
curl -fsSL https://pkg.workbuddy.com/key.gpg | sudo gpg --dearmor -o /usr/share/keyrings/workbuddy.gpg
echo "deb [signed-by=/usr/share/keyrings/workbuddy.gpg] https://pkg.workbuddy.com/apt stable main" | sudo tee /etc/apt/sources.list.d/workbuddy.list
sudo apt update && sudo apt install workbuddy
Tip · 国内网络
在 ~/.zshrc 里加 export WORKBUDDY_REGION=cn，包下载走 CDN，平均提速 4x。

Handbook · 02MCP 连接

让 AI 伸手 摸到你的数据

MCP（Model Context Protocol）让大模型可以安全、可控地调用外部工具。本节解释协议本身、列出内置 MCP、给出自定义 server 的标准做法，以及 6 类常见连接错误。

§ 2.1

什么是 MCP

30 seconds explainer

MCP 是 Anthropic 在 2024 年底开源的开放协议。它把「工具调用」这件事标准化：一个 server 暴露一组带 schema 的工具，一个 client（也就是 WorkBuddy）按需调用，结果回传给模型。这样不同数据源（Notion、Slack、内部数据库）能用同一套机制接入，不需要为每个工具写适配器。

对用户来说，配置一次 MCP，所有 Skill 都能自动用上这个能力。比如接了 GitHub MCP，HR Skill 可以看候选人仓库、研发 Skill 可以分析 PR、法务 Skill 可以拉合规清单——三件事用同一根线。

↔
标准化
一套协议覆盖所有数据源。开发者写一次，企业全公司复用。
●
可控
每次调用都需用户授权，敏感操作走二次确认。日志全留痕。
⚡
组合
多个 MCP 可以链式调用。一次提问触发 3 个数据源协作。

§ 2.3

添加自定义 MCP

Custom server

WorkBuddy 的 MCP 配置目录是 ~/.workbuddy/mcp/servers.json。每个 server 包含 name、command、args、env 四段。WorkBuddy 在启动时扫描这个文件，无需重启即可热加载（除系统级 MCP）。

~/.workbuddy/mcp/servers.jsonJSON
{
  "mcpServers": {
    "internal-crm": {
      "command": "node",
      "args": ["/opt/mcp/internal-crm/dist/index.js"],
      "env": {
        "CRM_TOKEN": "${secret:internal_crm_token}",
        "CRM_BASE": "https://crm.internal.workbuddy.com"
      },
      "description": "公司内部 CRM 数据",
      "permission": "read"
    },

    "weather": {
      "command": "uvx",
      "args": ["mcp-weather-server"]
    }
  }
}
Secret 注入
不要把 token 明文写在配置里。用 ${secret:NAME} 占位，真实值放在 ~/.workbuddy/secrets.enc（系统级加密，权限 600）。WorkBuddy 启动时会要求 Touch ID / 系统密码解锁一次。
§ 2.4

6 类连接错误及排查

Troubleshooting
  • spawn ENOENT — command 路径不对。绝对路径优先，例如 /usr/local/bin/uvx 而不是 uvx。
  • Permission denied: /var/... — macOS 沙箱拦截。系统设置 → 隐私 → 完全磁盘访问 → 启用 WorkBuddy。
  • SSL: CERTIFICATE_VERIFY_FAILED — 企业代理替换了证书。导入公司根证书到系统钥匙串。
  • Connection timed out (5s) — 网络层没问题但 server 没回包。先 wb mcp test <name> 看启动日志。
  • Schema validation failed — server 端 tool 定义不符合 MCP spec 1.0。用 wb mcp schema <name> 检查。
  • 401 Unauthorized — token 过期或被回收。重新走 OAuth 流程，或 wb secret rotate <name>。

Handbook · 03Skill 创建

把你脑子里的剧本 装进 AI

Skill = 一份结构化提示词 + 一组工具 + 一个触发场景。本节走通一个真实例子：从「报销审核 Skill」的需求拆解到上线发布，再到团队复用。

§ 3.1

Skill 的本质

What a Skill really is

很多同事第一次写 Skill 会把它当成"提示词模板"。其实 Skill 是四件事的封装：

  • 人感开场 — 一段"我是谁、我擅长什么、我会先问什么"的自我介绍，决定 AI 怎么开始对话。
  • 工作流剧本 — 把任务拆成 N 步，每步明确输入、动作、输出、确认条件。
  • 工具调用约定 — 哪些 MCP / 命令可以用、用之前要不要再确认、敏感数据怎么处理。
  • 输出规范 — 表格 / Markdown / PDF / 邮件？要不要署名、要不要附时间戳、要不要带源链接。

§ 3.3

实战：写一个「报销审核」Skill

Hands-on

假设你是财务，想让 AI 帮你预审每月 200+ 张报销单。下面是从需求到上线的全过程。

SKILL.md点击复制
--- name: expense-audit version: 1.2.0 description: 报销单预审 · 节省财务 70% 重复劳动 trigger: "审核报销" / "看下这张单" author: finance-team tools: - approve_rules.query - mailer.send permissions: - read_reimbursement_table - send_email_to_requester --- # 报销预审员 · 小审 你好，我是小审。我会按公司《费用报销管理制度 v4.2》帮你过一遍报销单。 我会先看金额、用途、票据、附件，再决定是通过、退回修改，还是转人工。 ## 我的工作流 1. 接单：你贴单号 / 截图 / 描述，我先去 reimbursement 表里把原始数据拉出来。 2. 分档： - ≤ 500 元，且用途、票据齐全 → 直接通过 - 500 ~ 5000 元，需检查是否在部门预算内 - > 5000 元，必须附说明 + 部门负责人确认 3. 查规则：调用 approve_rules.query 核对当前生效的政策。 4. 输出：返回一张三列表（项 / 状态 / 建议），并标出需财务人工复核的红旗项。 ## 我会问什么 - "票据是否齐全？" - "是市内交通还是差旅？" - "是否已超出部门当月预算的 80%？" ## 我不会做什么 - 不会直接打款 - 不会修改任何原票据 - 不会绕过 > 5000 元的硬规则
技巧 · 拒绝模糊
把所有"看情况"翻译成"先问 X，再做 Y"。SKILL.md 越像新员工入职手册，AI 越稳定。写完大声读一遍，如果听起来像机器人，重新写。

PR-01 · JD 优化复制
你是资深招聘编辑。我会贴给你业务方一段话和过往 JD。 请输出 3 个版本： 1. 正式版（官网 / 拉勾用） 2. 友好版（BOSS / 脉脉用） 3. 雇主品牌版（LinkedIn / 微信视频号用） 每个版本包含：岗位价值主张、3 条核心职责、2 条加分项、薪酬带宽、面试流程时长。 最后做一次 性别中立词 + 年龄偏见 + 学历歧视 检查，列出问题词与替换建议。
PR-02 · 简历三档分级复制
我给你 N 份简历 + 1 个 JD。请按以下规则分级： - 强推：JD 命中 ≥ 80%，经验在 80–120% 区间 - 备选：命中 60–80%，或经验 50–80%（潜力股） - 不匹配：命中 < 60% 每份简历给出：3 条匹配理由 + 1 条最大疑虑。不要给最终录用建议。 如果有候选人履历明显造假或时间线对不上，标红提示。
PR-03 · 面试纪要模板复制
你将听到一段面试录音 / 看到一份逐字稿。 请输出一份结构化纪要： - 候选人：姓名、应聘岗位、面试官、时长 - 关键回答：3–5 条原话引用 + 你的观察 - 能力雷达：业务理解 / 沟通 / 学习力 / 文化匹配 / 抗压（5 分制） - 风险点：1–3 条 - 建议：推进 / 待定 / 不推进（含一句话理由） 不要替面试官写最终结论。

提示词样例

Prompts
PS-01 · 客户研究 5 段式复制
我给你一个 公司名 + 我的产品。请用 5 段式输出客户画像： 1. 公司基本面：行业、规模、融资、最近 12 个月动作（每个事实必须附公开来源） 2. 关键人：3–5 个可能对接的角色、职级、可能痛点 3. 触发事件：最近 3 条新闻 / 财报 / 招聘信号 4. 价值主张：用 1 句话讲清楚我的产品能解决什么 5. 反对意见预判：他们最可能问的 3 个问题 + 应对方向 最后给一段 ≤ 80 字的首次外联邮件。
PS-02 · Pipeline 周报复制
我会贴一份 CRM 导出。请输出本周 Pipeline 评审： 1. 数字：机会数 / 总金额 / 加权金额 / 转化率（vs. 上周 / 上月） 2. 停滞：14 天无动作的机会，按金额排序前 5 3. 需介入：5 家，下一步动作建议 4. 本周赢 / 输：各 3 家 + 原因归类 5. 下周 3 个重点 不超过 800 字，给老板看。
