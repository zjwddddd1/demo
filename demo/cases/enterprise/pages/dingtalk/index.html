关键技术决策 · 为什么这么选

决策点选择理由
大脑选型乐享知识库检索（RAG）比裸接大模型准确、可溯源、低幻觉；比接完整 CLI 轻量、响应快
消息接收方式Stream 长连接程序主动建 WebSocket，无需公网域名、备案、反向代理与开放端口
知识库鉴权乐享独立端点 + 静态令牌脱离客户端授权态，服务器进程用静态令牌即可独立调用乐享检索

部署形态 · systemd 守护

本地运行生产服务器 systemd
会话回收即终止注册为系统服务，独立于任何会话
休眠 / 关机掉线服务器 7×24 不关机
进程崩溃无人接管崩溃自动拉起 ＋ 开机自启 ＋ 定时刷新连接
!
三条最值钱的经验：一是大脑选型——知识库问答场景，用「乐享知识库检索」最优；二是凭证独立性是生死线，动手前先验证服务器进程能否脱离客户端独立调用乐享；三是常驻进程必须上服务器，systemd 守护才是 7×24 在线的唯一正路。

    程度：多维表读 / 写已实测打通（场景一上线）；普通在线文档正文为富文本块结构，读取可行，精准写入排版仍是难点，需再验证。

    审批
    读+发起可做 · 自动签字慎用
    程度：查审批实例、程序发起审批、监听状态变更事件均可做；程序自动同意 / 拒绝技术可行，但等同机器人替人签字，属流程责任问题，建议永远保留人工兜底。
    典型场景
  • 报销 / 请假提交后 → 自动播报到群「某人提交报销，待审批」
  • 超过 N 小时未审批 → 自动催办；极低风险审批满足条件自动通过
    • 🔔
    事件响应（被动）
    可做 · 复用长连接
    程度：在场景二已有的 Stream 长连接上追加注册事件回调即可，无需新开连接。订阅审批任务 / 实例变更等事件。
    典型场景
  • 审批状态变更 → 自动播报结案 / 触发后续待办
