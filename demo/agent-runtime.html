百度三面备战 · Agent 运行时 Demo 技术详解

这个 Demo 做了什么？用什么做的？

一句话：一个零框架的最小 Agent 运行时 —— 本地 HTTP 服务 + 插件化工具 + ReAct 编排循环 + 可视化 Trace，可选接入大模型做真实推理。

① 先纠正一个关键混淆：ReAct 模式 ≠ React 框架

你说「用了 React 框架」——不对，这里没有 React 你看到的"react"其实是 ReAct 模式（Reasoning + Acting，Agent 的「推理 → 行动」编排循环），是 Agent 领域的一种编排范式，不是 Meta 的 React 前端框架。名字像，完全是两码事。
ReAct 模式（本 demo 用的）「推理 + 行动」交替循环：模型先想（Thought）→ 决定调哪个工具（Action）→ 看结果（Observation）→ 再想…直到给出最终回答（Final）。是 Agent 的核心工作方式，写在 index.html 的编排循环里。
React 框架（本 demo 没用）Meta 开源的前端 UI 库，用来写网页界面（组件化、虚拟 DOM）。本 demo 的前端是原生 HTML/CSS/JavaScript，没有任何前端框架。
面试时主动说清这点是加分项 「我用的不是 React 框架，是 ReAct 模式——推理与行动交替的 Agent 编排范式」——这种主动澄清能证明你真懂，不是背名词。

③ 用了什么框架 / 技术栈：答案是「零框架」

前端

原生 HTML + CSS + JavaScript（单文件 index.html），无 React/Vue 等任何框架，无 CDN 依赖，离线可用。

后端

Node.js 原生 http 模块（server.js），无 Express 等框架、零 npm 依赖，一条命令启动。

数据

JSON 文件（data/customers.json 客户档案、data/knowledge.json 知识库），本地读写，数据不出域。

大模型

可选接入任意 OpenAI 兼容接口，默认配置百度千帆 ernie-4.5-turbo-128k，通过后端 /api/chat 代理调用。

L4

ReAct 编排循环 + 6 个插件化工具 + Trace 记录 + 后端工具 API。

L1

模型与算力层

可选大模型（默认千帆 ERNIE）+ 本地 JSON 数据 + 沙箱命令执行。
